# 2026.329.0011 — docs: the image must ship nvidia-smi for the free-VRAM gate

## Summary

State the image-level dependency the free-VRAM gate actually has: **`nvidia-smi` must exist in the
image**.

The gate samples free VRAM by exec'ing `nvidia-smi` before it spawns the worker. CDI injects the
driver *libraries* at runtime, not the CLI, so an image that composes this candy without
`nvidia-utils` answers `503 gpu_unavailable` — `nvidia-smi was not found, but
QWEN3_TTS_DEVICE=cuda:0 requires an NVIDIA GPU` — on **every** synthesis request, and never starts a
worker. That is exactly what the consumer's disposable bed hit on a `base: cachyos` image that
composed only this candy (opencharly/distro-cachyos, wave commit `ddcb8a9`, which now composes
`@github.com/opencharly/layer-nvidia`).

Changed:

- `.agents/skills/qwen3-tts/SKILL.md` — a paragraph in **Deployment**: the image must ship
  `nvidia-smi` (`nvidia-utils`, installed by `layer-nvidia`), why CDI does not supply it, and the
  exact 503 an image without it produces.
- `README.md` — the same fact next to the VRAM-lifecycle row, naming the composing box as the
  reference.

Docs only: no code, no manifest, no pin.
