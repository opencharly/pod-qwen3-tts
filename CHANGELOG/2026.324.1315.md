# 2026.324.1315 — feat(qwen3-tts): consume opencharly/Qwen3-TTS and unload after idle

## Summary

Consumes the org's Qwen3-TTS fork and adds the one custom behaviour the stack needs.

- `pixi.toml` — `qwen-tts` moves from PyPI `0.1.1` to
  `{ git = "https://github.com/opencharly/Qwen3-TTS", tag = "v2026.324.1131" }`, the fork's
  CalVer tag; `pixi.lock` is committed and records the tag's commit
  (`86598b4486e81e80c8edc8d3f1daca41dff0cf7e`). Torch resolves to `2.14.1+cu130`.
- `qwen3-tts-server.py` — `QWEN3_TTS_IDLE_UNLOAD_S` (default `0`; the deployment sets `300`)
  releases the checkpoint after the TTL. A synthesis touches the timer, and the unload takes the
  synthesis lock non-blocking, so a running render is never unloaded mid-call. `/health` reports
  the `unloaded` state (503) and the next request reloads.
- `tests/test_idle_unload.py` — the in-diff witness: it loads the installed server, seeds a
  loaded fake state, starts the idle thread and asserts the release plus the `unloaded`
  readiness answer; it fails if the thread/start helper/touch hook is reverted. The candy copies
  it and a plan check (`qwen3-tts-idle-unload-unit`) runs it.
- `charly.yml` — declares the env, installs and runs the test, and asserts the `unloaded`
  readiness state.
- `README.md` / `.agents/skills/qwen3-tts/SKILL.md` — name the fork/CalVer handle and the idle
  knob.
- `.gitignore` — ignores the local `.pixi/` environment directory (the lock is committed, the
  resolved env is not).

The fork itself (opencharly/Qwen3-TTS#1, tag `v2026.324.1131`) carries the export fixes and the
honest 0.6B `instruct` warning.
