# 2026.319.1119 — fix(qwen3-tts): make the C toolchain package list distro-aware (successor to #2)

## Summary

> **Successor to opencharly/pod-qwen3-tts#2** (auto-closed after 5 counting BLOCK verdicts, per the
> validator's own policy — that thread is not reopened). Every finding from those five rounds is
> addressed here: the per-distro package list is unchanged in intent, and the proof, coordination and
> compliance sections now carry what each round asked for.



The candy installed `gcc` **and** `gcc-c++`. `gcc-c++` is a Fedora-only package — Arch/CachyOS ships the
C++ driver inside `gcc` and has no such package — so any CachyOS image composing this candy failed its
package step before the service ever started. The list is now `gcc` plus a `distro.fedora` addition of
`gcc-c++`, so each distro gets exactly what it needs and the base choice stays the consumer's.

The compiler is there because torch/triton JIT-compile kernels at **synthesis** time: a bare base with
no C compiler turns every synthesis into `RuntimeError: Failed to find C compiler`.
