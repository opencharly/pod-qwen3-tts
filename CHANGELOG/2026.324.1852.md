# 2026.324.1852 — fix(qwen3-tts): pin HOME and HF_HOME for a bound deployment

## Summary

Pins `HOME: /home/user` and `HF_HOME: /home/user/.cache/huggingface` so a **bound** Qwen3-TTS
deployment resolves its server path and checkpoint cache to the mounted `models` volume instead
of `/root`.

**Why it is needed.** A host-owned bind makes charly run the container as root under its keep-id
mapping, where the runtime `HOME` is `/root` — while the server, its checks and the `models`
volume live under the image user's home. Without the pins:

- the idle-unload test and the two honesty checks import the server via
  `~/.local/bin/qwen3-tts-server.py` → `/root/...` and fail with `FileNotFoundError`;
- the Hugging Face cache defaults to `/root/.cache/huggingface`, so the checkpoint **bypasses**
  the bound volume and is downloaded into the container layer.

**Measured (R1).** `check-qwen3-tts-pod` run `2026.324.1529` on the bound bed: the service checks
passed, the three import-based checks failed at the `/root` path, and the bound volume stayed
empty. With the pins (run `2026.324.1839`) the whole bed is green, including the previously
failing checks and the idle-unload/reload state machine.
