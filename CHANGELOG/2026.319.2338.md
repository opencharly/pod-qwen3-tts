# 2026.319.2338 — fix(qwen3-tts): make the speech service recoverable, honest and self-describing

## Summary

The OpenAI-compatible speech shim (`qwen3-tts-server.py`) turned one transient condition into a permanent, silent failure, in five ways; this change fixes all five and adds an optional style instruction.

- **Sticky load error.** The model-load exception was cached in `_state["error"]` for the process lifetime, so a single CUDA OOM wedged synthesis until a restart — no retry, even after the memory freed. The load is now retriable: the next request that finds no load in flight performs a fresh attempt, `load_attempts` counts them, and the last failure is retained for diagnostics.
- **Dishonest readiness.** `/health` answered `200 {"status":"ok"}` while the service could not synthesize at all. It is now a real readiness signal — `503` with a machine-readable `status` (`loading` | `unloaded` | `error`) plus `detail`, and `200` only once the model serves — while `/v1/models` keeps answering `200` throughout (that is the OpenAI surface a consumer probes).
- **Cold start outlasts the consumer.** The checkpoint loaded on the FIRST request (8–33 s measured), which exceeds the consumer's request timeout, so the first "speak" after any restart failed with `Server Connection Error`. The load now starts in a background thread at process startup; a request arriving during warm-up waits for the one in-flight load (single-flight), and the blocking load and model call run off the event loop so `/v1/models` and `/health` stay responsive. Synthesis stays serialized — the upstream model is not documented thread-safe.
- **`response_format` ignored.** The handler always wrote WAV regardless of the request, so a consumer declaring `{"response_format":"mp3"}` was silently served something else (and had to transcode). The server now measures the formats its installed encoder can actually produce at import (`wav`, `pcm`, `flac`, `mp3` on libsndfile 1.2.2), honours the requested one, and answers `400` naming the supported set for anything else.
- **Unvalidated `model`, hardcoded voices.** The request's `model` field was never read, so a client addressing the wrong model was silently served, and `/v1/audio/voices` was a hardcoded 9-item list that would advertise phantom voices after a checkpoint swap. A foreign model id now gets `400 model_not_served`, an unknown voice gets `400 unsupported_voice`, and the voice list is derived from the model's own `get_supported_speakers()` (the hardcoded list survives only as a logged fallback before the model loads).
- **New: optional style instruction.** `QWEN3_TTS_INSTRUCT` (deployment default) and a request's `instruct` field are forwarded to the model's `instruct` kwarg, which the CustomVoice path already accepts. Unset means the model's own default.

`charly.yml` gains two deterministic plan checks for the contracts that were missing — the voice contract and the single-flight/retry guarantees included. `README.md` and `.agents/skills/qwen3-tts/SKILL.md` document the new behaviour, and `.gitignore` keeps the `__pycache__` artifact a check run generates out of the tree.

Failure and recovery, measured on one process with the real checkpoint (CPU device, spare port, scratch process): an absent checkpoint produced `503` with `detail` and `load_attempts=1`; the next request retried (`503`, `load_attempts=2`); after the cause was repaired the following request loaded and served 99,884 B of real WAV, `/health` moving to `200 {"load_attempts":3}`. That is the sticky-error fix proven as behaviour, not as a code read.

Not exercised: the GPU device path inside the bed (the bed's venue allocated the card, but the synthesis probe's device is the image default) and an R10 run on a host with no GPU contention. Neither is claimed.

## Change classification

No `!`: no consumer of this repo is broken by the change. The visible semantic changes are deliberate and strictly more honest — `/health` now answers `503` while the checkpoint warms or has failed (it previously answered `200 "ok"` in states where it could never synthesize), and an unsupported `response_format`, foreign `model` or unknown voice now returns `400` instead of being substituted. The in-tree consumer (`pod-openwebui`) does not read `/health`, and declares `{"response_format":"mp3"}`, which is now honoured directly instead of arriving as WAV.

Rollback: revert this PR (or re-pin the previous image tag). No data migration is involved; the on-disk checkpoint cache is read, never rewritten.
